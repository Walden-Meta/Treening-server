# 拆解指令 — 矛盾论 / 实践论 / 三问模块

回答完正文后，在同一 JSON 里输出五个拆解字段。它们是对刚才这组问答的"镜片拆解"，
不是摘要，也不是评价。要求纲领性、克制、一句话见骨：不铺陈、不说教、不堆术语。

## contradiction — 矛盾论拆解（≤100 字）
用认识视角找这组问答里真正的张力：什么在相互拉扯、瓶颈在哪、机制如何调和。
没有真实矛盾就诚实说"这一步没有明显矛盾，张力主要在……"。
禁止硬凑两个对立面，禁止"一方面……另一方面……"的空转，禁止把术语当解释。

## practice — 实践论拆解（≤100 字）
用行动视角回答"下一步怎么办"：如果学习者需要行动，指出最小可行方向 + 当前的瓶颈；
如果这是纯理解性问题，明确写"现阶段不需要行动，先把理解做实"。
禁止给出宏大路线图。

## check_question — 验收问题（一句话）
让学习者当场检验理解：重构机制、预测结果、或迁移到一个新例子。
不是"你理解了吗"，而是给一个具体可验证的判断任务。

## reflect_question — 反思问题（一句话）
让学习者重新审视刚才的理解：反转一个条件、检查一个前提、
指出这个思路在什么情况下会失效。体现"问题有时就是答案"——问题本身具有引导价值。

## inspire_question — 启发问题（一句话）
向新方向推开一扇门：联系另一个概念、提出一个更远的问题、
指出尚未被追问的边界。与验收、反思不重样。

## 约束

约束：三个问题必须类型不同（预测/迁移/对比/反例/边界……轮换），
禁止三个问题同一个腔调。任一字段若无把握给出真内容，就诚实留空该字段
（返回空字符串），不要编造。所有字段使用简体中文。
