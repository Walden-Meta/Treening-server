# textree 前端设计与交互演进路线

## 1. 文档目的

本文档用于指导 textree 在保留原有知识树、三分支、节点阅读和扑克牌收起交互的前提下，逐步形成稳定、清晰、有辨识度的产品界面。

设计参考苹果与小米的共同语言，但不直接复制其组件：

- 苹果式的层级、克制、空间连续性和细腻反馈；
- 小米式的信息效率、年轻感和高饱和状态色；
- textree 自身的树生长、路径聚焦和扑克牌收起。

目标不是让界面“更像某家公司”，而是形成属于 textree 的空间化学习体验。

## 2. 产品设计定位

### 2.1 核心定位

textree 应从“带知识树的网页”演进为：

> 一张以路径为核心、以画布为空间、以节点为思考入口的智能学习桌面。

### 2.2 三个设计关键词

```text
路径优先
空间连续
操作隐退
```

#### 路径优先

用户默认需要读懂当前学习链路，而不是同时看清整棵树的全部文字。

#### 空间连续

节点聚焦、全树概览、路径切换和收起展开应该保持方向与位置关系，避免突然跳变。

#### 操作隐退

按钮和工具只在用户需要时出现。画布、当前节点和学习内容才是主要视觉中心。

### 2.3 非目标

- 不为了高级感堆叠大量毛玻璃；
- 不让所有模块同时变大；
- 不用动画掩盖状态错误；
- 不牺牲节点结构可读性来追求完整全图；
- 不将桌面三栏简单缩小后塞进手机；
- 不为了模仿苹果而失去 textree 的分支色和牌堆特征；
- 不在 UI 核心版本稳定后持续进行低收益视觉微调。

- 收起解析层已有 4 项单元测试。

### 3.2 当前字体

```css
font-family:
  Inter,
  ui-sans-serif,
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  sans-serif;
```

实际表现：

- Windows 英文和数字通常为 Inter 或 Segoe UI；
- Windows 中文通常回退到微软雅黑；
- macOS / iOS 通常使用 SF Pro 与苹方；
- 当前没有内置 Web Font，加载成本低，但跨平台字形存在差异。

### 3.3 已完成的基础优化

- 白底黑字的黑白灰主题；
- 蓝、橙、紫三类高饱和分支色；
- 统一基础字号和模块层级；
- 桌面工作区高度对齐；
- 1024px 下历史与阅读面板抽屉化；
- 手机端画布优先；
- 当前入口和工具栏分层；
- 全图最低缩放提升至 32%；
- 低倍率概览状态隐藏低价值控件；
- 响应式历史和阅读面板；
- 旧模板兼容保护；
- 父子嵌套收起关系由独立解析层管理。

### 3.4 已实测的界面基线

#### 1512 × 982

- 三栏结构成立；
- 左栏约 220px；
- 中央画布约 771px；
- 右栏约 390px；
- 顶部区域约 137px；
- 画布约 574px 高；
- 输入区约 178px 高。

#### 1024 × 768

- 历史与阅读区进入抽屉；
- 中央区域接近全宽；
- 当前入口和工具栏为两行；
- 画布约 344px 高；

- 输入区位于画布下方，首屏不可见。

## 4. 当前主要矛盾

### 4.1 宣传页标题与生产力工作区

大标题有品牌感，但在已有主题中持续占用工作空间。空白状态需要情绪表达，工作状态需要效率。

### 4.2 完整结构与文字可读性

整棵树适配到 32% 时可以理解结构，但无法直接阅读文字。继续增大节点只会让全图更难适配。

### 4.3 丰富功能与画布主中心

历史、阅读、工具栏、导出和输入区都很重要，但不能与画布争夺第一视觉层级。

### 4.4 动画表现与状态正确性

扑克牌收起是品牌交互，但嵌套收起、路径视图和连续操作必须先有明确状态归属，之后才能增加动画。

### 4.5 年轻感与视觉克制

年轻感应来自高效层级、流畅响应和有目的的状态色，而不是更多装饰、渐变和阴影。

## 6. Phase 0：冻结视觉与功能基线

### 6.1 工作内容

- 保存 1512×982、1024×768、390×844 三档截图；
- 记录主要模块矩形和字体；
- 记录当前缩放比例、节点数量和树深度；
- 检查控制台错误；
- 验证现有交互。

### 6.2 功能基线

- 新建主题；
- 历史主题切换；
- 节点选择；
- 节点拖拽和缩放；
- 画布缩放和拖拽；
- 回到全图；
- 隐藏和显示；
- 收起和展开；
- 父子嵌套收起；
- 删除节点子树；
- 导出完整树、当前路径和当前子树；
- 移动端面板开关。

### 6.3 完成标准

任何后续阶段都可以与基线截图和功能清单直接比较。

## 7. Phase 1：设计令牌和应用框架

### 7.1 设计令牌

建议将当前零散数值逐步归并为变量：

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 20px;
  --space-6: 24px;

  --radius-control: 10px;
  --radius-card: 16px;
  --radius-panel: 20px;
  --radius-pill: 999px;

  --text-meta: 11px;
  --text-control: 12px;
  --text-body: 14px;
  --text-reading: 16px;
  --text-section: 20px;
}
```

变量名称表达语义，而不是绑定某个模块。

### 7.2 双状态页头

#### 空白状态

- 保留“让一个问题，长出自己的路径”；
- 保留简短产品说明；
- 提供明确的首次输入入口。

#### 工作状态

- 收缩到约 64～72px；
- 显示 textree、当前主题、节点数量、深度；
- 将新主题和配置放到右侧；
- 滚动、恢复主题或存在节点时进入工作状态。

### 7.3 验收标准

- 空白状态有品牌感；
- 工作状态至少释放约 60px 垂直空间；
- 状态切换不造成画布突然跳动；
- 移动端标题不超过两行；
- 键盘焦点与屏幕阅读器顺序稳定。

## 8. Phase 2：悬浮思考坞

### 8.1 默认状态

- 宽屏最大宽度约 720～820px；
- 画布底部居中；
- 高度约 64～76px；
- 仅显示输入框、当前分支和发送；
- 提示文字在非聚焦时隐退。

### 8.2 聚焦状态

- 展开到约 130～160px；
- 显示追问、验收、自定义、新问题；
- 保留 Shift + Enter 换行；
- 不覆盖当前焦点节点；
- 使用渐变遮罩保证后方画布可辨认。

### 8.3 移动端

- 适配 `safe-area-inset-bottom`；
- 软键盘打开时保持输入和发送可见；
- 底部阅读面板打开时避免两层固定组件竞争；
- 必要时回退为普通文档流输入区。

### 8.4 验收标准

- 输入坞默认高度显著低于当前约 178px；
- 输入、提交和分支选择功能不变；
- 不遮挡小地图、节点操作或系统键盘；
- 390px 宽度下没有横向溢出。

## 9. Phase 3：视图解析层

### 9.1 数据流

```text
原始节点数据
→ 收起状态解析
→ 视图解析
→ 布局
→ DOM / SVG 呈现
```

视图解析只决定“当前需要呈现什么”，不得改变原始节点关系和用户收起意图。

### 9.2 当前路径模式

- 默认展示根到当前节点的完整路径；
- 保留当前节点必要的直接分支入口；
- 路径节点使用正常可阅读比例；
- 非路径节点不进入主布局或进入弱化背景层；
- 当前节点切换时保持空间方向。

### 9.3 邻近分支模式

- 在当前路径两侧显示一层兄弟分支；
- 只显示角色、分支和一句摘要；
- 降低透明度和操作权重；
- 点击后成为新的当前路径；
- 时间紧张时可作为当前路径模式的二期能力。

### 9.4 全树模式

- 用于理解结构和导航；
- 不承担完整文字阅读；
- 低倍率自动隐藏按钮和长正文；
- 保留小地图；
- 选中节点后可切回当前路径模式。

### 9.5 与收起解析层的关系

- 父节点收起后，其后代由父节点牌堆拥有；
- 被祖先覆盖的子收起意图保持潜伏；
- 祖先展开后，子收起意图恢复；
- 当前路径不能绕过有效收起根强行显示后代；
- 切换视图不能修改收起意图；
- 每个被收起节点只能属于一个牌堆。

### 9.6 验收标准

- 当前路径和全树可重复切换；
- 当前路径中文字可读；
- 不出现重复节点、孤立连线或错误牌堆；
- 收起解析测试持续通过；
- 视图模式测试覆盖路径、分支和潜伏收起组合。

## 10. Phase 4：节点三级视觉状态

### 10.1 焦点节点

- 宽度约 320～360px；
- 显示完整摘要或正文；
- 分支色带清楚；
- 操作按钮可见；
- 阴影和边框层级最高；
- 键盘焦点与视觉焦点一致。

### 10.2 路径节点

- 宽度约 260～300px；
- 显示两到三行摘要；
- 保留角色和分支；
- 操作按钮在悬停、聚焦或选中时出现。

### 10.3 背景节点

- 一行摘要；
- 降低边框、文字和阴影；
- 隐藏操作按钮；
- 保留分支色和结构关系；
- 点击后成为焦点节点。

### 10.4 色彩规则

- 黑白灰承担结构；
- 蓝色表示追问；
- 橙色表示验收；
- 紫色表示其他探索；
- 分支色用于色带、连线、圆点和选中光晕；
- 避免大面积高饱和背景。

### 10.5 验收标准

- 用户能在一秒内识别当前焦点；
- 低倍率下没有无意义的小按钮噪点；
- 分支类型不依赖颜色单独传达；
- 文本对比度满足基本可访问性要求。

## 11. Phase 5：节点检查器

### 11.1 信息层级

```text
角色 / 分支 / 深度
节点标题
完整正文
当前路径
父节点摘要
后代数量
上下文操作
```

### 11.2 上下文操作

- 定位节点；
- 收起或展开后代；
- 隐藏或显示内容；
- 导出当前路径；
- 删除问题子树，仅在用户节点和明确确认后出现。

### 11.3 防止信息过载

- 默认展开正文和当前路径；
- 元数据与低频操作折叠；
- 路径过长时只显示最近三级；
- 空状态显示最近焦点或使用提示，而不是加入装饰卡片。

### 11.4 验收标准

- 节点卡片和检查器状态同步；
- 隐藏节点不会在检查器中泄露正文；
- 右侧面板与中央工作区等高；
- 中屏和手机使用可关闭底部面板；
- `Esc`、遮罩和切换按钮行为一致。

## 12. Phase 6：历史区升级为学习轨迹

### 12.1 信息结构

- 今天；
- 最近 7 天；
- 更早；
- 空白主题归入“草稿”。

### 12.2 会话信息

建议显示：

- 主题标题；
- 节点数量；
- 树深度或路径数量；
- 最近更新时间。

只有定义严谨时才显示百分比进度。若无法定义“完成”，应使用：

```text
26 节点 · 深度 5 · 今天
```

而不是虚构学习完成率。

### 12.3 验收标准

- 标题支持两行；
- 不出现内层横向滚动；
- 空白草稿不淹没有内容主题；
- 历史切换后视图、阅读区和当前节点正确恢复。

## 13. Phase 7：统一动效语言

### 13.1 生长

- 连线先沿父节点方向出现；
- 节点随后从父节点方向进入；
- 新节点获得短暂焦点；
- 不使用无来源的随机弹跳。

### 13.2 聚焦

- 当前节点轻微提升；
- 从根到当前节点逐级点亮；
- 非关联节点降低对比；
- 画布移动到舒适阅读位置；
- 方向变化保持连续。

### 13.3 收起

- 后代按深度和位置依次进入父节点下方；
- 卡片间延迟约 25～40ms；
- 连线同步向父节点回缩；
- 父节点显示“已收起 N”提示；
- 展开严格按照相反关系恢复；
- 父节点始终处于牌堆上方并可点击。

### 13.4 模式切换

- 当前路径与全树使用连续缩放和透明度；
- 不突然清空再重建；
- 切换后焦点节点仍可追踪；
- 动画完成状态与关闭动画时的结果一致。

### 13.5 时长建议

| 类型 | 时长 |
|---|---:|
| 按钮反馈 | 120～180ms |
| 面板开关 | 240～300ms |
| 节点聚焦 | 320～420ms |
| 牌堆收起 | 450～650ms |

### 13.6 性能约束

- 优先使用 `transform` 与 `opacity`；
- 避免大量节点同时动画 `left`、`top`、宽度和高度；
- 使用 FLIP 或等效方法保持布局连续；
- 拖拽和缩放期间对小地图更新节流；
- 超过一定节点数量时只动画当前路径；
- 保留 `prefers-reduced-motion`；
- 动画中连续操作必须以状态机或可取消动画处理。

## 14. 响应式规格

### 14.1 宽屏：≥1440px

- 左栏约 210～220px；
- 中央画布自适应；
- 右侧检查器约 380～400px；
- 栏间距约 20～24px；
- 当前入口和工具栏可在一行；
- 思考坞居中悬浮。

### 14.2 紧凑桌面：1360～1439px

- 左栏约 190px；
- 右栏约 340～360px；
- 当前入口与工具栏允许两行；
- 导出等低频操作可以进入更多菜单。

### 14.3 中屏：861～1359px

- 画布作为唯一主列；
- 历史和阅读区使用抽屉或底部面板；
- 工具栏保持水平排列；
- 不将三栏压缩为狭窄列；
- 输入坞不得覆盖抽屉控制。

### 14.4 手机：≤860px

- 紧凑页头；
- 历史和阅读按钮紧邻工作区；
- 当前入口单行省略；
- 工具栏允许横向滚动或收起低频操作；
- 画布优先；
- 阅读区和历史区为底部面板；
- 思考坞适配软键盘。

### 14.5 小屏手机：≤560px

- 主标题 28～30px；
- 工具栏隐藏低频下拉框；
- 节点宽度约 250～270px；
- 小地图缩小或允许关闭；
- 胶囊操作横向滚动；
- 确保 44px 左右的主要触控区域。

## 15. 字体层级

| 用途 | 建议范围 |
|---|---:|
| 空白状态主标题 | 42～46px 桌面 / 28～30px 手机 |
| 工作状态主题标题 | 18～22px |
| 模块标题 | 18～21px |
| 阅读正文 | 16～17px，行高 1.7～1.8 |
| 普通正文 | 14～15px |
| 历史标题 | 13～14px |
| 节点摘要 | 12～13px |
| 控件 | 12～13px |
| 元数据 | 11～12px |

原则：

- 避免低于 11px 的实际可见文本；
- 使用字重、对比和空间建立层级；
- 减少全大写和过宽字距；
- 不依靠颜色区分唯一含义；
- 字体加载失败时不应造成布局崩溃。

## 16. 留白使用规则

### 16.1 应扩大

- 中央画布；
- 当前路径；
- 历史记录有效内容；
- 阅读正文和路径摘要；
- 空树时的首次输入入口。

### 16.2 应压缩

- 已有主题下的大型宣传标题；
- 长篇固定说明；
- 重复图例；
- 始终展开的低频导出选项；
- 大型输入表单外壳。

### 16.3 不应填满

留白不需要全部变成卡片。只有能帮助用户判断路径、状态或下一步的内容才应该占据空间。

可用于有效填充的信息：

- 节点数量；
- 当前深度；
- 最近更新时间；
- 当前路径摘要；
- 后代数量；
- 最近主题；
- 空树引导。

## 17. 性能边界

### 17.1 节点数量策略

| 可见节点数量 | 表现策略 |
|---:|---|
| 0～50 | 完整动画和阴影 |
| 50～100 | 限制同时运动节点，减少模糊与阴影 |
| 100～200 | 只动画当前路径，背景节点直接就位 |
| 200 以上 | 评估节点虚拟化、分区或层级加载 |

这些是设计降级档位，不是未经测量的性能承诺。

### 17.2 已知关注点

- 当前 `renderGraph()` 会遍历并更新全部节点；
- 节点更新和测量会影响布局；
- `applyTransform()` 会刷新小地图；
- SVG 发光滤镜在大量连线下可能增加绘制成本；
- `backdrop-filter` 在低端移动设备上成本较高；
- `left/top` 动画在大量节点下可能触发布局和绘制。

### 17.3 验证指标

- 首次渲染耗时；
- 视图模式切换耗时；
- 拖拽和缩放帧率；
- 收起和展开帧率；
- 内存占用；
- DOM 节点数量；
- 小地图刷新频率；
- 30、100、200 节点下的差异。

## 18. 可访问性

- 所有图标按钮必须有可访问名称；
- 当前选中、展开、收起和隐藏状态需要 ARIA 表达；
- 抽屉打开后管理焦点，关闭后返回触发按钮；
- 键盘能够选择节点、打开阅读区和切换模式；
- 不以颜色作为唯一分支标识；
- 文本和背景保持足够对比；
- 支持减少动画偏好；
- 删除、导出等操作具有明确反馈；
- 隐藏内容不能通过阅读区或辅助文本意外泄露。

## 20. 防止设计漂移的决策门

添加新视觉元素前必须回答：

```text
它解决什么用户问题？
它属于信息、操作、反馈还是装饰？
不添加会造成什么实际损失？
是否与已有元素重复？
在手机端放在哪里？
是否增加持续动画或绘制成本？
是否影响键盘和辅助技术？
如何验证它有效？
```

如果主要答案是“看起来更丰富”，默认不加入。

### 核心版本

1. 冻结视觉与功能基线；
2. 设计令牌；
3. 双状态页头；

1. 邻近分支模式；

4. 更完整的键盘操作；
5. 视觉回归自动化；
6. 展示级动效细化。

### 完成后的停止点

当核心版本达到以下条件，应停止继续进行低收益视觉打磨，转向后端工程路线：

- 三档主要尺寸稳定；
- 当前路径模式可读；
- 收起动画和逻辑正确；
- 输入与阅读操作高效；
- 产品具有明确的 textree 辨识度；
- 没有明显可访问性和性能缺陷。

后续方向见 [后端工程化与高流量演进路线](./backend-evolution-roadmap.md)。

## 22. 最终成果判断

### 22.1 轻量升级版

包含页头、思考坞、节点视觉和检查器，预计实现完整构想的约 65%～75%。开发风险较低，视觉收益明显。

### 22.2 完整产品版

包含当前路径、全树、节点三级状态、检查器、响应式和核心动画，预计实现构想的约 85%～95%。这是推荐交付目标。

### 22.3 展示级精品版

增加逐帧连续动画、大规模节点虚拟化、多浏览器精细调优。边际收益下降，不应挤压后端工程化工作。
